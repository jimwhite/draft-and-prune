1. Entities:
    - Clients: Image (0), Solide (1), Truvest (2)
    - Request Types: Website (0), Voicemail (1)
    - Target Days: 1, 2, 3

2. Variables:
    - `target_days = Array('target_days', IntSort(), IntSort())` - Maps a composite client/request type ID to a target day.  The composite ID is calculated as `client * 2 + request_type`.

3. Constraints:
    - Constraint 1 (Domain): `ForAll([i], And(target_days[i] >= 1, target_days[i] <= 3))` where `i` ranges from 0 to 5 inclusive.  Declare `i = Int('i')`.
    - Constraint 2 (Website <= Voicemail): `ForAll([c], target_days[c * 2 + 0] <= target_days[c * 2 + 1])` where `c` represents the client and ranges from 0 to 2 inclusive. Declare `c = Int('c')`.
    - Constraint 3 (Image Voicemail < Others Voicemail): `And(target_days[0 * 2 + 1] < target_days[1 * 2 + 1], target_days[0 * 2 + 1] < target_days[2 * 2 + 1])`
    - Constraint 4 (Solide Website < Truvest Website): `target_days[1 * 2 + 0] < target_days[2 * 2 + 0]`
    - Constraint 5 (Truvest Website < Truvest Voicemail): `target_days[2 * 2 + 0] < target_days[2 * 2 + 1]`

4. Answering the Question:
    - Create a base Z3 solver with constraints 1 through 5.
    - For each answer choice:
        - Push the solver state.
        - Add the negation of the constraint corresponding to the answer choice:
            - A: `target_days[0 * 2 + 1] != 2`
            - B: `target_days[0 * 2 + 0] != 2`
            - C: `target_days[0 * 2 + 0] != 1`
            - D: `target_days[1 * 2 + 0] != 2`
            - E: `target_days[1 * 2 + 0] != 1`
        - Check `solver.check()`. If `unsat`, store the answer choice letter as a *must be true* option.
        - Pop the solver state.
    - The correct answer is the stored answer choice letter.  If multiple or no answer choices are stored, the problem or the implementation is flawed.
