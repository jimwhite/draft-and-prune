3. Add **domain constraints**: each `pos[r] ∈ [1,6]`, and all `pos[r]` are pairwise distinct (a permutation of 1..6).  
4. Add **guitarist constraint**: guitarist does not perform the fourth solo → `pos[0] != 4`.  
5. Add **percussionist-before-keyboard constraint**: `pos[2] < pos[1]`.  
6. Add **violinist-before-keyboard-and-keyboard-before-guitarist constraints**: `pos[5] < pos[1]` and `pos[1] < pos[0]`.  
7. Add **saxophonist constraint**: saxophonist performs after *exactly one* of percussionist or trumpeter → `(pos[3] > pos[2]) XOR (pos[3] > pos[4])`.  
8. Translate answer choices to role indices: guitarist=0, keyboard player=1, saxophonist=3, trumpeter=4, violinist=5.  
9. Define an answer index list `answer_index_list = []`. For each candidate role r in [0,1,3,4,5]:  
   - Clone the base constraints into a fresh solver.  
   - Add constraint `pos[r] == 3`.  
   - If the model is UNSAT, then role r **cannot** be third; append r to `answer_index_list`.  
10. Print `answer_index_list` (should contain exactly one index).
